## Findings, by what they cost the player

### 1. The window keeps a second state per conversation, beside the jobs model

Where: Agent.lua 180-232 (`working`, `wasWorking`, `transcribing`,
`TRANSCRIBE_FOR = 15`), 234-289 (the board), 548-604 (`handlers.log` starts and
ends the waiting line), 641-645, 937-940 (`TALK_HELD`), 945-955. Jobs.lua 250-292
(the work entry; its last word is chosen by comparing `endedAt` with
`live.began`). ChatWheel.lua 179-206 (dictation's 6 s wait). Link.lua 63-94 and
Pad.lua 37-52 (the game's own copy of the PC's tap and slot rules).

Why: The PC names every clip and request by job id and sends each state.
JobsModel.lua holds them and is property-tested. But "hearing", "working", the
work entry, its last word ("answered below", "stopped", "cancelled") and
dictation's wait come from other tables. Message kinds set them; timers (15 s,
6 s) or the game's guess of the clip clear them. This is the "second state
machine" that docs/proposals/conversation-sync.md blames for the last round of
bugs. Eleven fixes this morning were here, and none of it is tested. Two live
bugs follow from it: with the agents off, `WC.ChatChannel.Dropped` is never
called (only Agent.lua 552 calls it), so a dropped dictation clip shows
"transcribing" for 6 s; with them on, any error line in any conversation ends
a dictation wait.

Smallest fix: Put the work line in the model: per running job, its latest
progress text and when it began (`progress` and `heard` already carry the job).
Draw hearing lines, the work line, its end word and the board from the model
only. Give dictation clips a job too (main.rs 483-493), so their wait ends on
it. Then delete `working`, `wasWorking`, `transcribing`, `setTranscribing`,
`settleTranscribing`, the 15 s and 6 s timers, `Dropped`, and the slot rule in
Link.lua 66-77. `TALK_HELD` hides latency; if it stays, it must follow the
design's own rules for predictions (named by identity, settled honestly), which
it does not now. Measure `heard`'s arrival in timing.log first.

### 2. Voice events are strings cut and parsed by shape, and the request path is written twice

Where: crates/voice/src/lib.rs 276-306, 447-469, 475 build roles such as
`"ask@r2 notice"`. main.rs 413-646 takes them apart with `ends_with`,
`strip_prefix` and `trim_end_matches`. main.rs 355-412 (typed requests) repeats
508-632 (spoken ones): the lock, the queued line, `run_queued`, `IN_FLIGHT`,
`ask`, the failure.

Why: This is the class `message.rs` closed on the way to the game, still open on
the way in. A misrouted clip notice was fixed once already (c18fb25). A fix to
one request path misses the other. `run` is 431 lines because of both.

Smallest fix: `voice::Event` as an enum (`Tap`, `Released { slot }`,
`Words { slot, text }`, `Dropped { slot, why }`, `NoAudio { slot, why }`) over
a `Slot` enum (Main, L1, L2, R1, R2, Quick, Dictation). main.rs matches on it.
One `fn request(slot, text, job)` serves the voice loop and the typed queue.

### 3. The channel knows the UI session by two keys and reads the save file four ways

Where: channel.rs 332-355: the slot cursor's session is Core's save mtime plus
the game's start time ("near enough", line 342). channel.rs 447-456: the bell
set is Link's load count. channel.rs 50-58: `slotCount` by `text.find`, else
"the old 64". backups.rs 153-180: `loads` by a hand-written depth scanner.
context.rs 32-61: the export by `find`, with its own unescaper (only `\n` is
turned back). backups.rs 196-298: `lua_sound`, "not a parser", a third scanner.
savedvars.rs 1-2 calls itself "the one reader of the save file"; it is one of
four. `RELOAD_OFFERED` (requests.rs 359-367), `watch_for_looks` (41-65) and
`addon_is_stale` (channel.rs 366-373) each derive the session again.

Why: The cursor and the bell set must match the game exactly, or a message is
taken early, late or never. Today's lost chat line (7c5f962) came at a session
boundary, and its fix added one more check keyed on the mtime stamp. Each hand
reader can disagree with the game's format on its own.

Smallest fix: One `Session { loads, game_started }` read once from Link's save
through `savedvars::global`, used by the cursor, the bell set, the reload offer
and the look watcher. `known_slots`, `loads` and `saved_string` become
`savedvars` lookups; `lua_sound` becomes "the file parses". This changes the
channel, so per CLAUDE.md it runs beside the live one and switches only after a
session's counts agree.

becomes true. `SCHEMA` can stay a raw string.
